# c9n 0.9.39

**Updates: kurze Sicherung statt stundenlanger Auszeit.** Die Sicherung vor einem Update nimmt jetzt die Daten, die Datenbanken und die Konfiguration, aber nicht mehr die Arbeitsverzeichnisse der Agenten (Arbeitskopien, Zwischenspeicher, Programmverzeichnisse). Auf einer Installation mit 112 GB Gesamtdaten waren das früher über eine Stunde Auszeit, jetzt sind es 1,7 GB und wenige Sekunden. Was in `/data` neu dazukommt, wird automatisch mitgesichert. Es bleiben die zwei neuesten Sicherungen auf dem Host, ältere werden entfernt.

**Updates: Bei einem Fehler läuft die bisherige Version von selbst wieder.** Scheitert die Sicherung oder wird der Update-Dienst mitten im Update beendet, bevor die neue Version eingeschaltet wurde, startet c9n die bisherige Version wieder und gibt die Arbeit der Agenten und den GPU-Pool frei. Die Seite zeigt dann „Die bisherige Version läuft wieder“, und das Update lässt sich erneut starten. Vorher stand an dieser Stelle „Wiederherstellung auf dem Host erforderlich“. Nur wenn die neue Version bereits eingeschaltet war und nicht gesund startet, bleibt es dabei, weil die Daten schon angepasst sein können. Wird der Update-Dienst beim Herunterladen oder Prüfen beendet, wird die Bearbeitung ebenfalls wieder freigegeben.

**Aufträge: Zeitlimit und „Erneut versuchen“.** Ein Auftrag, der sein Zeitlimit erreicht hat, sagt das jetzt und zeigt die Stufe „Blockiert“. Administratoren können einen vom System gestoppten Auftrag mit „Erneut versuchen“ neu starten. Außerdem startet c9n einen vom System gestoppten Auftrag einmal von selbst noch einmal.

**Dokumentationsprozess.** Blockierte Dokumentationsaufträge melden sich per deutschem Kommentar im Jira-Ticket (einmal je Auftrag und Lauf); den Zeitplan des Skripts `docbits-blocked-notice.sh` trägt der Betrieb auf dem Host ein. Vor und nach dem Zusammenführen prüft c9n, ob die Seite im Inhaltsverzeichnis steht, die Bilder vorhanden sind und die Veröffentlichung bei GitBook sichtbar ist. Ein wieder aufgenommener Auftrag wiederholt Schritte nicht, die schon als erledigt gemeldet wurden.

Hinweis: Während ein Update auf laufende Agentenaufträge wartet (bis zu drei Stunden), ist die Annahme neuer Arbeit angehalten. Wer das vermeiden will, startet das Update, wenn nichts mehr läuft; das Abbrechen und ein gezieltes Beenden laufender Aufträge folgen in einer späteren Version.
