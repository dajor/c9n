# c9n 0.9.4

Das c9n-Image enthält die native Agentenausführung und Zeitplansteuerung zusammen mit GPU-Pool, Git, GitHub CLI, Browser, Jira-Anbindung und den Werkzeugen der ursprünglichen Hub-Prozesse. Alle c9n-Dienste verwenden dasselbe versionierte Image. Für die Übernahme einer bestehenden Installation wird der vollständige Arbeitsbestand einschließlich Profilen, Schlüsseln, Ergebnissen und Arbeitsverzeichnissen in ein eigenes c9n-Datenvolume kopiert und geprüft. Die bisherige Ausführung muss dafür pausiert und vollständig beendet sein.

Eigene Modellagenten können über „Auftrag starten“ tatsächlich arbeiten. Beim ersten Start erhalten sie ein privates Ausführungsprofil aus der eingerichteten Standardmodellverbindung. Der Auftrag übernimmt die gespeicherte Agentenaufgabe sowie seinen Prozess und Schritt. Ergebnis und Laufhistorie bleiben nach dem Neuladen erhalten. Fehlende Modellverbindungen und widersprüchliche Profile werden mit einem Fehler angezeigt. Das Anlegen oder Speichern allein startet keinen Auftrag.

Die ursprünglichen Scan- und Veröffentlichungsaufträge erscheinen beim passenden Prozess und Akteur. Der Katalog enthält auch die bisher fehlenden Betriebsakteure. Direkte Auftragslinks öffnen nach der Anmeldung den gewählten Auftrag. Ursprüngliche Aufträge zeigen ausführenden Agenten, Zulauf, letzten Lauf, Ergebnis und benötigte Rückmeldung bei einer Blockade. Beim lesenden Anschluss werden geöffnete Aufträge automatisch aktualisiert; Lesefehler erhalten den zuletzt gelesenen Stand.

Prozessdiagramme öffnen direkt auf einer großen Leinwand. Die alternative Schrittliste, Zoom, Verschieben und Einpassen bleiben verfügbar. Ein abgebrochener Bearbeitungswechsel erhält den vorherigen Ausschnitt und die Auswahl.

Updates prüfen Platz für die vollständige Datensicherung einschließlich großer Agentenarbeitsverzeichnisse. Eine verwaltete Ausführung lässt laufende Arbeit beenden, bevor Dienste angehalten werden. Die Sicherung erhält für große Datenbestände entsprechend mehr Zeit. Während der Sicherung und des Neustarts ist die Installation vorübergehend nicht erreichbar. Updates werden weiterhin ausdrücklich bestätigt.

## Grenzen

Ein lesend angebundener Altbestand wird durch das Update allein noch nicht zum ausführenden c9n-Bestand. Die geprüfte Übernahme und der Wechsel der Ausführungsautorität sind erforderlich. Eine aktive Modellverbindung sowie gültige Zugänge zu den genutzten Diensten bleiben Voraussetzung. Alte Aufträge und menschliche Freigaben werden erhalten; blockierte Veröffentlichungsaufträge benötigen eine gezielte Klärung und Fortsetzung ihres bestehenden Auftrags.

Neue grafische Prozessdefinitionen werden durch einen ausdrücklichen Start des zugeordneten Agentenauftrags ausführbar. Das vollständige automatische Routing aller grafischen Schritte und neue Bruno-Zeitpläne sind weiterhin nicht eingerichtet. Kalles Code wird statisch geprüft und nicht ausgeführt. Der ursprüngliche Videoablauf bleibt ein Entwurf; pausierte Wächter bleiben pausiert. Ein erfolgreicher Zeitplanlauf allein bestätigt keine Veröffentlichung. Das Installationspaket unterstützt Linux auf amd64.
